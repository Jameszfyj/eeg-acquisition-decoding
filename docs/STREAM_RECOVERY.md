# 实时预测与接收恢复

## 默认设置

实时工作台默认每0.1秒（10 Hz）更新预测，适用于已接入的ONNX、MI Studio v2及原生PT模型。模型输入窗口、通道、参考、单位、采样率、预处理和权重按各模型约定保留。独立使用模型库时的输入配置与工作台在线调度分别记录，见[模型接入](MODEL_IMPORT.md)。

除仅显示的四分类入口外，默认使用投票判决：2秒滚动窗口、65%得票、3.5秒最长等待、4秒动作间隔。每个概率向量的最高概率类别获得一票；不能把它理解为概率累加。页面中显式选择的判决模式和参数优先。

## 丢包、暂停与投票

- 丢包次数和缺失时长不作为停止条件。每个收到且校验通过的原始包照常保存，时间轴缺口不拼接、不补点。
- 包序号或设备时间出现缺口：重置滤波/模型缓存，只剔除原始支撑（含因果 FIR 历史）跨缺口的 slice。重新获得完整干净窗口后继续加入投票。
- 投票轮的有效票和起始时刻保留。提前多数判决仍使用滚动窗口；最长等待到时，使用本轮全部有效 slice 的最高票类别，票数相同依次比较平均概率与最近有效票。到时只有一张有效类别票也可判决；没有类别票（包括全平票弃权）则本轮无输出。计时不依赖新预测到来，禁止重复使用上一概率补票。
- 超过1秒未收到有效脑电：保持连接并显示接收暂停；已开始的投票轮仍按原倒计时结束。
- 收到积压数据：逐包比较已通过校验的设备时间与包序号。若连续，原始数据照常归档，并按原设备样点顺序进入同一滤波/模型状态；不因主机接收停顿、接收速率突增或队列积压而跳过推理、重置滤波。
- 到达延迟与缺样分开记录。已到截止时间的投票不重开；动作中的预测不排队，下一次动作仍要求提示或回位后边界以后的完整窗口。软件边界通过独立设备时钟映射估计，不能直接取最后到达的旧包。
- 带提示试次不因丢包重做、不改变目标或试次 ID；累计 `packet_loss_events`。机械手动作中及动作间隔内不积累票，已经执行的动作不会再次下发。
- 观察界面显示缺口/校验异常次数、已知缺失点数、是否等待完整窗口、有效票数与剩余倒计时。`protocol_events.jsonl` 保存逐次异常，`report.json` 和原始 H5 的 `stream_quality` 保存汇总。

离线录制按原计划推进，不因反复丢包或暂停而中断。原始质量标记保留供训练筛选；[离线试次验证](OFFLINE_ONNX_VALIDATION.md)也仅跳过受影响窗口，继续后续评分。

## CRC与停止条件

重复半包只有在逐字节前缀相同、后续完整包CRC和帧尾均独立通过时才被识别为`duplicate_prefix`，原始字节及完整包证据保留。不会拼接坏包或修改载荷。

CRC/帧尾/载荷错误由解析器拒绝，不信任坏包头部的时间戳。后续校验通过的帧若与前一个有效帧连续，保留原滤波状态；只有确认设备时间或包序号不连续才重建干净窗口。CRC 通知本身不丢弃此前已验证的排队数据，没有每分钟 CRC 次数限制。

真正的连接关闭、设备时钟回退/重叠、设备配置改变、队列溢出、写盘失败及被试页面失联仍停止并保留证据。`stalled` 仅表示暂未收到数据，不再当作连接关闭。到达速率因丢包或网络批量到达而下降/上升不改变设备的已核验采样率。

## 验证范围

自动测试使用合成信号、模拟串口和本机TCP，覆盖0.1秒窗口节奏、长短暂停收、重复/大缺口、CRC隔离、连续补发的模型输入与概率一致、软件时钟映射、设备时间回看、无新预测的超时判决、空票无输出及离线连续评分；验证缺口后 FIR 支撑与独立连续片段输入一致。没有以真实设备动作作为自动测试。

## 显示与软件时钟

在线实时波形、离线实时波形和历史回看均按设备样点时间排列。实际设备时间缺口显示留白；到达停顿后连续补发不会把时间轴压缩或拉伸。网络接收点/秒与设备采样率分开，回看点数图按设备时间每秒统计。H5 仍同时保留设备时间与主机到达时间。

软件打标使用主机单调时钟减去已观察到的最小主机/设备时间偏移，将指令发出时刻估计到设备采样轴，避免最近一个迟到包拖动标记。它不能测定绝对传输延迟、设备长期漂移或声光物理呈现时刻；保留 `physical_onset_verified=false`。硬件回传仍使用设备事件时间。
