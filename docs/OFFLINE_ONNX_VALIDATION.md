# 离线录制中的 ONNX 验证

采集工作台（默认 http://127.0.0.1:57373）的实验设置中，可以上传模型 ZIP，或单文件 ONNX 加配套 `manifest.json`。沿用 `handbci.onnx.v1` 输入约定；单独的图不能确定电极顺序、预处理、单位和类别，因此不能省略清单。

导入检查后勾选“每个试次结束后验证”。被试、采样率、单位、通道名称及任务名称必须与模型对应；任务排列可以不同，评分按名称映射。每次开始都会固定模型并复制到该次记录内。未启用时沿用原来的采集流程。

每个任务结束、收到结束标记及对应脑电后，后台用 **0.5 秒步长**回放全部完整窗口。准备锚点模型从 prepare 网格取窗，包含准备期；其他模型要求完整原始支撑位于 cue 之后。所有窗口止于 task_end 之前，不读休息信号，不提前触发结束。因果滤波、模型归一化及频带转换与在线 ONNX 解码共用实现。

每窗最高概率类别记一票，最高概率精确平票时弃权。最终取整试次最高票类别；票数相同时比较平均概率，再相同则显示未判定。面板同时展示平均概率、得票率、票数。此口径是整段模拟多数票，并非在线控制器的提前触发或超时规则。任务标签只用于事后评分，不传给模型或投票器。

被试面板仅在休息、轮间休息和会话结束时显示结果；后续试次开始即隐藏，迟到结果不会作为新试次的分数显示。不延长或改动采集时序。原始采集和模型验证由不同线程执行；模型或写盘故障会显示错误并保留原始采集。

丢包、CRC 异常或接收暂停不终止离线录制，也不终止后续试次验证。设备时间与包序号缺口保留；每个连续片段分别滤波，剔除跨缺口或因果 FIR 历史不足的窗口，仍按原设备时间轴的 0.5 秒网格投票，不拼接或补点。每试次保存 `gap_count`、`skipped_windows` 及剩余有效窗口得分。有有效 slice 就正常展示各类概率、得票和预测，不显示整段跳过；所有候选 slice 都受 Gap 或其滤波历史影响时，显示“传输异常”，保存 `status=transmission_error`，下一试次继续。窗口网格覆盖计划的完整任务时间，包括丢失的尾段或整个试次。任务本身短于模型窗口、未完成或缺少标记时另记具体原因。软件估计标记或落在时间缺口中的标记不计入已核验标签命中率。训练兼容性检查仍保留原始质量限制，完成录制不等于数据可用于训练。

选择“软件标记”后可直接录制，无需连接 TriggerBox 或进行回传自检。软件事件在后端发出任务指令时立即记录 `mono_time_ns` / `wall_time_ns`，不等待硬件发送/确认线程，也不以计划时间替代实际发出时间；`planned_mono_ns` 仅作时序诊断。按最近 EEG 包的接收时钟估计设备时间，并将可对齐的事件保存到事件表和 H5 `trigger` 通道。事件保留 `trigger_mode=software`、`marker_time_source=host_command_issue`、`echo_verified=false`；估计位置落在缺口时不移到缺口之后。休息段仍按有效窗口展示模型得分。

任务结束后优先等已排队的脑电到达结束边界；若指令发出已超过 0.5 秒且队列为空，则用已有完整 slice 显示暂算反馈（`status=waiting_data`、`provisional=true`）。尚未到达的尾部记为待补窗口，不直接判为 Gap，不计入最终完成次数。迟到数据补齐后按全部有效 slice 完成评分，仅向结果文件写入一次最终票数；录制结束仍缺尾部时，保存已有有效票或“传输异常”，并记 `end_boundary_received=false`。后续试次照原计划继续。

录制目录中的 `onnx_validation/` 包含：

- `model.onnx`、`manifest.json`：本次使用的模型副本。
- `metadata.json`：模型指纹、类别顺序、窗口及投票约定。
- `predictions.jsonl`：有效窗口的样点边界、概率、累计票数和得分；被剔除窗口的边界和原因（无概率、无投票）。样点边界按设备时间轴计算，包含真实缺口。
- `trials.jsonl`：已处理试次的最终结果、传输异常或无法评分的具体原因，逐条刷新写盘。
- `summary.json`：全部试次、验证状态和已核验标签命中统计。

`session.json`、H5 元数据及 `collection_report.json` 保留验证配置/结果入口。原始 EEG、counts、标记和训练标签不被预测替换。采后查看支持按试次回看评分。启用反馈本身会改变采集条件，因此元数据明确记录 `feedback_phase=rest`，供后续比较使用。
