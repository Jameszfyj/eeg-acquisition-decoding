# 离线录制中的 ONNX 验证

采集工作台（默认 http://127.0.0.1:57373）的实验设置中，可以上传模型 ZIP，或单文件 ONNX 加配套 `manifest.json`。沿用 `handbci.onnx.v1` 输入约定；单独的图不能确定电极顺序、预处理、单位和类别，因此不能省略清单。

导入检查后勾选“每个试次结束后验证”。被试、采样率、单位、通道名称及任务名称必须与模型对应；任务排列可以不同，评分按名称映射。每次开始都会固定模型并复制到该次记录内。未启用时沿用原来的采集流程。

每个任务结束、收到结束标记及对应脑电后，后台用 **0.5 秒步长**回放全部完整窗口。准备锚点模型从 prepare 网格取窗，包含准备期；其他模型要求完整原始支撑位于 cue 之后。所有窗口止于 task_end 之前，不读休息信号，不提前触发结束。因果滤波、模型归一化及频带转换与在线 ONNX 解码共用实现。

每窗最高概率类别记一票，最高概率精确平票时弃权。最终取整试次最高票类别；票数相同时比较平均概率，再相同则显示未判定。面板同时展示平均概率、得票率、票数。此口径是整段模拟多数票，并非在线控制器的提前触发或超时规则。任务标签只用于事后评分，不传给模型或投票器。

被试面板仅在休息、轮间休息和会话结束时显示结果；后续试次开始即隐藏，迟到结果不会作为新试次的分数显示。不延长或改动采集时序。原始采集和模型验证由不同线程执行；验证失败会显示错误并保留原始采集。跨 Gap、缺少完整窗口或未完成的试次明确记为跳过；软件估计标记可以得到预测，但不计入已核验标签命中率。

录制目录中的 `onnx_validation/` 包含：

- `model.onnx`、`manifest.json`：本次使用的模型副本。
- `metadata.json`：模型指纹、类别顺序、窗口及投票约定。
- `predictions.jsonl`：每窗样点边界、概率、累计票数和得分。
- `trials.jsonl`：已处理试次的最终结果或跳过原因，逐条刷新写盘。
- `summary.json`：全部试次、验证状态和已核验标签命中统计。

`session.json`、H5 元数据及 `collection_report.json` 保留验证配置/结果入口。原始 EEG、counts、标记和训练标签不被预测替换。采后查看支持按试次回看评分。启用反馈本身会改变采集条件，因此元数据明确记录 `feedback_phase=rest`，供后续比较使用。
